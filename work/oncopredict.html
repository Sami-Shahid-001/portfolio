OncoPredict AI

A breast-cancer diagnosis classifier made usable: a scikit-learn model behind a Flask API with consistent feature scaling, and a responsive JavaScript front end, deployed on Railway and Vercel.

01

The problem

A trained model in a notebook helps nobody. The goal was to take a breast-cancer diagnosis classifier all the way to something a person can use, enter measurements, get a prediction, without the model behaving differently in production than it did in training.

02

The model

The dataset has thirty numeric features per tumour. After cleaning and exploratory analysis of their distributions, features were standardised and split 70/30 for training and testing, and a logistic-regression model was trained on the standardised inputs for numerical stability and faster convergence.

03

From notebook to API

The Flask API applies the same fitted scaler before every prediction, the easiest bug in this kind of project is training on scaled data and serving unscaled data. The front end posts features over REST and renders the result in real time.

04

What holds, and what does not

What holds: the full path from notebook to a public web app, with consistent preprocessing on both sides.

What does not: it is a teaching model, not a medical device, a single model with no calibration study or clinical validation behind it.
